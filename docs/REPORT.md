# 四张 CMP 170HX 上的 DeepSeek V4.1 Flash 实测

测试日期：2026-10-18。测试使用本地模型权重和自编译 vLLM backport 环境。文档只发布汇总数据，不包含原始对话或主机标识。

## 结论

最终固定配置 3000-token 单流 Decode 样本落在 **47.84–58.65 token/s**；完整故事与代码任务分别约 **45.46 / 49.24 token/s**。单流 80 token/s 仍未达到。

八路混合任务端到端聚合吞吐为 **91.28–116.96 token/s**，是八路总和，不代表单请求速度。Prefill 的重复测量如下：

| 输入规模 | Prefill token/s | TTFT 秒 |
| ---: | ---: | ---: |
| 1K | 640.76–931.19 | 1.14–1.57 |
| 4K | 1784.35–2130.00 | 2.15–2.32 |
| 8K | 3099.78–3669.00 | 2.30–2.68 |
| 16K | 2920.00–5455.00 | 3.09–5.69 |

历史轮次测量范围与口径见 `../results/` 下 CSV 和完整工作簿。样本数有限，启动热身、缓存状态、输入文本与生成长度都会造成波动；这些数据不构成延迟 SLO 或 80 token/s 承诺。

## 第七轮：常驻 CPU 调度桥接

候选桥接用可被 CUDA Graph 捕获的 mapped-host 通知和常驻 CPU dispatcher 替代逐层 CUDA 主机回调。隔离测试里 4-token 桥接中位耗时由 **0.101757 ms** 降至 **0.056455 ms**，24-token 由 **0.346892 ms** 降至 **0.233425 ms**。三层真实专家权重、单路/八路形状、缓存命中和尾部 padding 共 **1188 次逐位一致**。

完整服务 A/B/A 对照：

| 配置 | 单流 Decode token/s | 八路端到端聚合 token/s |
|---|---:|---:|
| 原版 A1 | 49.98 / 47.97 | 102.71 / 108.09 |
| 候选 B | 51.61 / 51.51 | 105.94 / 113.70 |
| 恢复原版 A2 | 51.23 / 55.07 | 103.31 / 108.64 |

候选没有明确超出原版波动，故未采用。生产使用的原入口和原生库已恢复。候选实现依赖原模型执行流中 CPU 专家任务串行提交；没有验证任意多 CUDA stream 并发，不能作为通用库直接启用。

首次集成候选时漏链 Engram SSD 源文件，服务在模型加载前退出。补齐第二个源文件并核对生产库全部 19 个导出接口后才进行有效 B 测试。失败记录不包含在公开包中。

## 优化结论

禁用 P2P、保留全部专家与原量化是本机正确性基线。缓存调整、DSpark 查询位置/草稿数、CPU 预取、GPU 分块、主机传输打包与桥接替换都没有证明稳定提升，均未进入生产。单流要显著超过当前范围，需要重构 CPU 专家与 GPU 层的分工和流水线依赖；这不是简单改线程数能够保证的结果。

完整逐轮结果在 `../results/X99最终测试结果.xlsx`（19 张表）。每次 Decode 使用 completion token 数除以首末输出事件时间差；该口径计入首个增量，略偏高。八路聚合为整批输出 token 数除以整批墙钟时间。Prefill 使用服务端计算输入 token 数除以请求 prefill 阶段墙钟时间，前缀缓存命中为零。
